# Forever Rail Help Center

The public help site at **help.foreverrail.com**. Anyone can read it without signing in.

Articles are written and published by staff in the [operations dashboard](https://github.com/Forever-Rail-Community/ops-dashboard) (Help center in its sidebar). This site has no editor or database of its own: at build time it reads every published article from the dashboard's public feed and turns them into plain static pages, so it's fast and easy for search engines to index.

- **Astro 7**, fully static, hosted on Vercel
- **Pagefind** for search; the search index is built along with the site
- Light and dark mode: follows the device setting until someone picks one, then remembers it
- Site name, logo, and main color come from the dashboard's **Admin > Appearance**

## How publishing works

1. Staff publish an article in the dashboard.
2. The dashboard calls this site's Vercel deploy hook.
3. Vercel rebuilds this site from the feed. The change is live about a minute later.

## Setting it up on Vercel

1. In Vercel, **Add New > Project** and import `Forever-Rail-Community/help-center`. Vercel recognises Astro; keep the default build settings.
2. Under **Settings > Environment Variables**, add:
   - `HELP_FEED_URL`: required. The dashboard address followed by `/api/public/help`, for example `https://ops.foreverrail.com/api/public/help`.
   - `DISCORD_URL`: optional. An invite link for the "Join Discord" and "Ask on Discord" buttons.
   - `STATUS_URL`: optional. The status page, for the "Status" links.
   - `DASHBOARD_URL`: optional. Only needed if the dashboard link should point somewhere other than the address the feed comes from.
3. Deploy.
4. Under **Settings > Domains**, add `help.foreverrail.com` and create the DNS record Vercel shows you.
5. Under **Settings > Git > Deploy Hooks**, create a hook (any name, branch `main`) and copy its URL.
6. In the **dashboard's** Vercel project, set `NUXT_HELP_DEPLOY_HOOK` to that URL and redeploy the dashboard. From then on, publishing rebuilds this site.

The site needs Node 24 (set in `package.json`), which Vercel uses automatically.

## Working on it locally

```
cp .env.example .env     # then set HELP_FEED_URL
npm install
npm run dev              # http://localhost:4321 (search only works on a built site)
npm run build            # builds the site and the search index into dist/
npm run preview          # serves dist/
npm run check            # type check
```

## Where things are

- `src/lib/feed.ts`: loads the feed once per build and arranges categories, sections, and articles.
- `src/lib/render.ts`: turns an article's body into HTML. Keeps only content the editor can make, only `http(s)`/`mailto` links, and only `https` images. Text is always escaped.
- `src/lib/schema.ts`: the kinds of content an article can contain. **Keep this in step with the dashboard's `app/utils/helpEditor.ts`.** Content the editor saves that isn't listed here is left off the page.
- `src/lib/logo.ts`: copies the dashboard's logo into the build as `/logo.<ext>`.
- `src/pages/`: home, `/<category>/`, `/<category>/<article>/`, 404, robots.txt. The sitemap is generated by `@astrojs/sitemap`.
- `src/styles/global.css`: colors for light and dark mode, and all page styles.

Category web addresses share the top level of the site, so avoid `pagefind`, `_astro`, and `logo` as category addresses.
